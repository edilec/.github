# Support

This is the default support guidance for public Edilec repositories. Project
documentation may define a narrower or different support boundary.

## Public project support

Use the repository's issue forms for reproducible bugs and focused feature
proposals. Before opening an issue, review the README, supported versions,
known limitations, and existing issues.

Include:

- the repository and exact version or commit;
- the operating system, runtime, and relevant dependency versions;
- a minimal reproduction with sensitive values removed;
- the expected and observed behavior; and
- logs or screenshots only when they do not expose private information.

General questions may be closed when they are outside the documented project
scope, cannot be reproduced, or require access to a private deployment.

## Security and conduct

Do not disclose a suspected vulnerability in a public issue. Follow
[`SECURITY.md`](./SECURITY.md). Report community conduct concerns through
[`CODE_OF_CONDUCT.md`](./CODE_OF_CONDUCT.md).

## Service boundary

Public repository support does not include a response-time guarantee,
production operations, custom implementation, private debugging, or commercial
support. For company enquiries that are not open-source project issues, use
[edilec.com/contact](https://edilec.com/contact/).
